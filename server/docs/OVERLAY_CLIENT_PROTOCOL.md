# Клиентский оверлей Castle Fight v1 (RAM only)

Это дополнение к Map 3.0; старые карты и старые маркеры НЕ возвращаются.

**При загрузке игрока и полной готовности маршрутов** ядро Minestom берёт:

1. `CFCarpetZones.snapshot(...)` — точные скрытые строительные ковры;
2. `CFThreeLanes.pathSnapshot()` — готовые маршруты с координатами.

Перечень цветов берётся строго из `CFMarkerPalette.ALL`. Не определять лайн
«по ближайшему пути» и не группировать различные ковры только по команде.

Затем `CFOverlaySync` создаёт неподвижный снимок, сжимает его zlib и делит
на небольшие сообщения `castlefight:overlay_v1` до 16000 байт данных.
Передача один раз за текущую сессию игрока на выбранной карте, без запросов
по G, без дискового кеша, без повторной отправки при каждом спавне.

Fabric-мод принимает сообщения, проверяет структуру, лимиты и CRC32,
собирает фрагменты и декодирует в RAM. `CFOverlayMesh` один раз создаёт
цветную геометрию, а рендер читает только эту структуру.

**Клавиша G** меняет только `visible`. Никаких сетевых вызовов в обработчике G.
При отключении клиента RAM очищается. Повторный вход = одна новая отправка.

Размерные ограничения для защиты: 200000 клеток, 100000 точек маршрутов,
4 дорожки, до 4 МБ сжатых данных. Большие карты требуют потоковой версии
протокола в будущем, а не снятия ограничений без проверки.

Внешние карты лежат только в вынесенной папке сервера `maps/`; ни карты,
ни готовый клиентский JAR не должны храниться в Git. В Git находятся ТОЛЬКО исходники server/ и client/.

## Контрольный список

- `CFOverlayWireSelfTest` — контрольная сумма, перестановка частей, 4 пути.
- `CFOverlayMeshSelfTest` — границы одноцветных клеток и разные цвета.
- `bash build.sh server` и `bash build.sh client` собирают только выбранный проект; исходники не меняют.
- Полный Java 25 / Fabric 26.2 runtime ещё надо проверить на Fedora.
