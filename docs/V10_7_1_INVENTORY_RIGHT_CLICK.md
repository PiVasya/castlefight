# Castle Fight V10.7.1 — ПКМ в инвентаре и локальный допуск строительства

## Что делает игрок

1. Открыть **свой инвентарь** клавишей E.
2. **ПКМ прямо по предмету башни в ячейке инвентаря** (не по миру и не предметом в воздухе) — откроется клиентское подробное меню башни. Предмет не разделяется и не переносится от ПКМ. Закрытие возвращает в инвентарь.
3. Достать предмет башни в руку, выйти из инвентаря, подойти к своей строительной площадке.
4. ПКМ по **верхней грани центрального блока пола** под 3×3 зонами — если всё подходит, отправляется единственный `castlefight:tower_build_v1` и сервер строит башню после собственной проверки.
5. Если площадка неверная, клиент показывает короткую надпись над хотбаром **без запроса**. Длинных лоров и чат-спама нет.

## Что проверяется до отправки

- Предмет распознан по каталогу текущей расы, имеется активное соединение и нужный протокол.
- Снимок зон/маршрутов текущей карты уже пришёл в RAM.
- Клик только по верхней грани и с расстояния не больше 8 блоков.
- Квадрат 3×3 на одной высоте, все девять **точно одного цвета**, правильная команда и существующий лайн, без поиска ближайшей дороги.
- Клиентский чанк загружен, девять блоков пола твёрдые, объём 3×3×3 и блок над центром свободны.
- Защита от двойного ПКМ: краткий локальный интервал между отправками.
- Место для **будущей проверки средств** присутствует (`CFBuildEconomy`), но **в V10.7.1 экономики, цен и данных о балансе нет**. Результат `NO_ECONOMY` это НЕ «достаточно денег»; проверка средств будет активирована после появления ресурсной модели и синхронизированного серверного снимка баланса.

Сервер сохраняет окончательное право отказа: проверяет предмет с собственным токеном, расу, команду, дистанцию, геометрию, реальный мир, лимиты башен, интервал между соседними башнями, состояние матча и другие правила. Никакие данные клиента для этих правил не являются авторитетными.

Строительство через старый `PlayerBlockInteractEvent` **удалено**. Этот обработчик остаётся только для инструментов осмотра, улучшения и административного сноса. Это гарантирует, что обыкновенный ПКМ без клиентской проверки не построит башню. Для игроков без Fabric-клиента строительство пока недоступно.

## Сеть и производительность

- Открытие/листание меню по предмету — 0 дополнительных пакетов.
- Неверная позиция/нет каталога/нехватка данных о мире — 0 `tower_build_v1`.
- Успешный локальный допуск — 1 компактный `tower_build_v1` с ID башни и тремя целыми координатами.
- Снимки карты/каталога остаются разовыми, без запросов на каждый ПКМ.
- Протокол не менялся по сравнению с V10.7. Не требуется новая таблица ресурсов до реализации экономики.

## Регрессионный сценарий на Minecraft 26.2

1. `bash build.sh all` должен пройти серверные self-tests и все клиентские задачи (включая `cfBuildPreviewSelfTest` и `cfBuildEconomySelfTest`).
2. В инвентаре левый клик по предмету — обычное поведение; правый клик по постороннему предмету — обычное поведение; ПКМ по башне — меню, инвентарь не перемещает стек.
3. В меню увидеть HP/урон/расы/ветки развития и заметку об отсутствии экономики. Закрытие вернёт в инвентарь.
4. ПКМ предметом в воздухе НЕ открывает меню и НЕ отправляет стройку.
5. ПКМ по неверной стороне, чужой зоне, неполному или разноцветному 3×3 — только actionbar, сервер без запросов.
6. ПКМ по свободной валидной площадке — ровно одна башня. Второе немедленное нажатие не дублирует запрос.
7. Проверить смену расы `/cf race snow` и повторное меню в инвентаре.
8. Без модифицированного клиента обычный ПКМ не создаёт башню.

## Проверки вне Minecraft

Компилируются и выполняются чистые Java-проверки `CFBuildPreviewSelfTest`, `CFBuildEconomySelfTest`; полный клиентский Fabric build на Java 25 и фактический GUI должны пройти тест на Fedora. Наличие исходников не доказывает успешность игрового запуска.
