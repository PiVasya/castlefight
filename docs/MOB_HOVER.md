# КФ: характеристики моба при наведении (V9)

- При наведении прицелом на CFUnit клиент отправляет серверу **только ID сущности**.
- Сервер проверяет мир, существование моба и расстояние до игрока (максимум 16 блоков).
- Сервер присылает название, команду, лайн, урон и его тип, броню, скорость, дальность, интервал атак, критический урон и шанс; HP передаётся в целых десятых без округления баланса.
- Сервер сам обновляет данные **не чаще раза в 4 тика** и только когда они изменились. Клиент не опрашивает сервер каждый кадр.
- При смене прицела старые данные стираются; при выходе из игры стираются из RAM.
- Клиент показывает компактную панель в HUD. Полоска HP **без цифр, процентов и подписей**. Над самими CFUnit кастомное имя также содержит **только глифы полоски HP**; чисел и имени рядом с ней нет. Имя показывается в панели при наведении.
- Клавиша G и разметка карты не изменены. Карта по-прежнему передаётся один раз на входе, живые характеристики — по выбору моба.
- Каналы: `castlefight:mob_query_v1` и `castlefight:mob_stats_v1`. Протокол `CFMobStatsWire.java` в `server/` и `client/` должен совпадать побайтово. Корневой `build.sh` это проверяет.
- `bash build.sh server` и `bash build.sh client` выполняются независимо. Релиз `dist/CastleFight` полностью переносим, карты в Git не попадают.

## Проверка

1. Собрать сервер `bash build.sh server` и клиент `bash build.sh client` на Fedora (JDK 25).
2. Поместить готовый JAR в Fabric 26.2, подготовить Map 3.0, запустить сервер.
3. Навести прицел на боевого моба. Статы появляются слева сверху, HP — отдельной минимальной полоской.
4. Нанести урон. При сохранении наведения сервер обновит HP без нового клиентского запроса.
5. Перевести прицел мимо моба. Панель исчезает.
6. Нажать G: карта подсвечивается независимо от наведения.

Автономный протокольный тест: `dev.cf.CFMobStatsWireSelfTest`. Для Minecraft-рендеринга требуется реальный клиент.
