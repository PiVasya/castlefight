# V10.7.4 — короткое сближение на каждой тычке ближника

В обычном `CFTraceMeleeGoal` после начала каждой ближней атаки выполняются
**два очень коротких шага к текущему противнику**: не более 0.15 блока
за шаг (0.30 блока суммарно). Оба шага распределены по двум игровым тикам.

- Не требуется выяснять, попал удар или промахнулся: шаги запускаются на
  каждой обычной попытке удара.
- Нового поиска целей, запросов к серверу/клиенту, пересчёта A* или
  дополнительного диагностического сканирования нет.
- Используется существующий `CFSmoothGroundFollower` с проверкой столкновений,
  препятствий и обычными ограничениями движения.
- При смене/потере цели, выходе из радиуса атаки или завершении боевой цели
  оставшиеся шаги отменяются. Кулдаун, урон, броня и способности не изменены.
- Специальный AI короля `CFKingGuardGoal` не менялся: защита/возврат на трон
  продолжают работать по прежним правилам.
- Для клиента новый JAR не нужен: изменился только серверный исходный код.

## Проверки

`CFMeleeContactStepSelfTest` добавлен к обязательным тестам `server/build.sh`.
Он проверяет ровно два шага, отсутствие третьего и сброс при потере цели.

Кроме того, локально проверена компиляция цели с API-совместимыми заглушками
и моделирование последовательности двух шагов без вызова поиска маршрута.
Это не заменяет реальный запуск Minestom на Java 25.

Проверка на Fedora:

```bash
bash build.sh server
```

После успешной сборки заменить `core/` и `start.sh` в вынесенном сервере.
Карту `maps/my-arena` и содержимое `data/` не трогать.
