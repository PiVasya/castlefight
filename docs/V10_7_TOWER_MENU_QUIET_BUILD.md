# Castle Fight V10.7 — одна раса, меню башен, тихое строительство

## Для игрока

- При входе выдаётся только стартовый набор расы **Тьма**. Другая раса выбирается командой `/cf race snow` или возвращается `/cf race dark`.
- Команда `/cf kit` повторно выдаёт только выбранную расу; команды `/cf team red|blue` меняют сторону отдельно.
- Предметы башен не содержат длинного лора. Названия остаются, чтобы отличать предметы.
- **ПКМ предметом в воздухе** открывает клиентский экран с описанием башни и её существ.
- **ПКМ предметом по блоку** открывает тот же экран с предварительной проверкой позиции. Если подходит — кнопка «ПОСТРОИТЬ» активна.
- В меню есть просмотр характеристик мобов в волне (по одному профилю), способностей и следующих ступеней улучшений. Внутренние значения int10 переводятся в игровые HP и урон без лишнего дробного хвоста. Улучшения сразу не строятся, а выполняются старым инструментом.
- При неправильной позиции/команде кнопка постройки неактивна. Сообщения — в меню и в actionbar над хотбаром, без сообщений от КФ в чате.
- Сервер продолжает отдельно проверять дистанцию, предмет в руке, команду, расу, девять ковров 3×3 строго одного цвета, реальный пол, свободный объём, расстояние между башнями и лимиты. Клиент НЕ является авторитетом.

## Трафик

Клиент использует снимок зон `castlefight:overlay_v1`, уже передаваемый один раз при подключении, и **не опрашивает блоки мира/маркеры для определения цвета ковров**. Снимок сохраняется только в RAM.

Сервер шлёт сжатый каталог только после подтверждения наличия Fabric-мода существующим HELLO выстрелов или при смене расы/команды: `castlefight:tower_catalog_v1`. В нём серверные значения башен, существ, урона и брони — клиент не выдумывает баланс и не держит отдельные копии контента.

`castlefight:tower_build_v1` содержит ID башни и координаты центра. Отправляется **только по явному нажатию «ПОСТРОИТЬ» после успешной локальной проверки**. Открытие/листание меню и неудачные попытки не отправляют запросов. Пакет содержит только версию, ID и три целых числа, без графики и повторной отправки геометрии. Сервер повторно валидирует каждую попытку.

Минимальный тест: войти с модом, выбрать предмет, ПКМ в воздухе (статы); ПКМ по неверной/чужой зоне (нет сетевого запроса); ПКМ сверху в центре корректной площадки (кнопка активна); подтвердить (на сервере одна башня), затем `/cf race snow`, проверить смену набора и меню. Проверить, что чат не засоряется ответами КФ; console/diagnostics сохраняются.

## Затронутые классы

- `server/.../CFTowerSystem.java` — инвентарь, серверные решения, каталог, запросы.
- `server/.../CFPlayerNotice.java` — actionbar вместо чата в игровых командных ответах.
- `client/.../CFBuildClient.java` / `CFTowerScreen.java` — ПКМ, локальная проверка, экран.
- `client/.../CFBuildPreview.java` — чистые правила проверки цвета 3×3.
- Две одинаковые копии `protocol/CFBuildWire.java` — двусторонняя проверка `build.sh`.

## Проверки и ограничения

Новое: `CFBuildWireSelfTest`, `CFBuildPreviewSelfTest`. Встроены в обычную серверную и клиентскую сборку.

Проверка чистой Java-логики на доступном JDK 21 возможна; **полный Maven Java 25 / Gradle Fabric 26.2 build и реальную отрисовку экрана необходимо проверить на Fedora**. Никогда не выдавать проверку протокола за фактический игровой запуск.

Весь прежний CF Map 3.0, замки 3×3, короли, движение по дорожкам, 9-байтовый клиентский протокол стрел, G/O-оверлей и нетронутая карта остаются прежними.
