# Castle Fight V10.7.3 — ПКМ по предмету в инвентаре (Minecraft 26.2)

## Причина ошибки сборки V10.7.2

`InventoryScreen` не предоставляет `getLeftPos()` и `getTopPos()` в используемом Minecraft 26.2 API. Компилятор Fabric останавливался в `CFInventoryTowerMenu.java` на двух вызовах.

## Исправление

- `CFContainerOriginAccessor` — Fabric Mixin accessor к существующим защищённым полям `leftPos` и `topPos` класса `AbstractContainerScreen`.
- Accessor зарегистрирован в `castlefight.client.mixins.json`; не используются ни рефлексия, ни вычисление координат наугад.
- `CFInventorySlotHit` выполняет чистую проверку попадания мыши в координаты слота с учётом реального смещения инвентаря. Это важно, когда книга рецептов сдвигает окно.
- `CFInventorySlotHitSelfTest` запускается при `bash build.sh client` вместе с остальными клиентскими тестами, проверяет 28 случаев.
- ПКМ по предмету башни в инвентаре открывает локальное меню; обычные предметы и перемещение слотов не изменены.

## Проверка в игре

1. Обновить **только клиентский мод** из `dist/client/castlefight-client.jar` после `bash build.sh client`.
2. На сервере открыть инвентарь (`E`). ПКМ по башне должен открыть экран характеристик без изменения количества предметов.
3. Закрыть меню и убедиться, что вернулись в инвентарь.
4. Открыть книгу рецептов, если она доступна; повторить ПКМ после смещения окна.
5. ПКМ по обычному предмету не должен открывать меню КФ.
6. В мире ПКМ с предметом башни должен запускать только локальную проверку строительства.

Сервер, карта, протоколы, значения ресурсов, AI и баланс не изменены.

## Статус проверки

Проверены синтаксис скриптов, JSON регистрации Mixin, автономные Java-тесты слотов и целостность архива. Компиляция **всего Fabric клиента** на Minecraft 26.2/Java 25 ещё не подтверждена в этом окружении; требуется запуск на Fedora.
